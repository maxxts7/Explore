## Store schema (store/graph.json)
papers / concepts {id,name,summary,parent,origins[{paper,role,summary,notes}],locators[{section,page,paper}],sections[{heading,body}]} /
edges {id,type,source,target,hindsight,groundedIn,prose} /
themes {id,name,members[conceptIds],narrative} /
superthemes {id,name,members[themeIds],narrative} /
superedges {id,type,source,target,prose} (endpoints share a supertheme) /
tissueThemes {id,name,members[edgeIds],narrative} /
stories [{id,tab,name,claim,narrative,ref{kind,id}|null,children[]}] — a LIST of rooted trees (each a lens over the whole corpus); per story every theme is placed exactly once (total), superthemes optional but all-or-nothing; node ids unique across ALL stories (they become DOM ids on one index page); tab label required + unique when >1 story. Legacy single `overlay` key still validated/rendered if present. /
paperStories [{id: paperId, stories: [same node shape as stories]}] — per-paper story pages (site/story/<paperId>.html), each paper telling itself in several lenses (convention: "Inside the paper" / "Across the corpus" / "The big picture"); NO total-coverage rule, but refs must resolve, a theme at most once per story, node ids unique within the paper's entry (they become DOM ids on that page), tab labels unique per paper, intros required and format-validated; coverage total over papers (every paper needs an entry, so a 5th paper's entry must land in the same `apply` transaction) /
themes[].walk [{concept,prose}] — member concepts in reading order with connective prose; covers exactly the members (validated) /
intro (optional, on concepts/themes/superthemes/tissueThemes/stories) — gentle two-paragraph page introduction: para 1 mild plain-language intro, para 2 roadmap of what the page shows; validated exactly-two-paragraphs, 35-160 words, no wiki-links

figures (stage 51; story form stage 52) — top-level dict keyed by paper id: {items: [{id, kind: figure|table, label, page, section (verbatim heading), classification: data-and-experiments|results-and-interpretation, image: "figures/<pid>/<fid>.png" (relative to store/; merge verifies the staged file and copies it in after validation), note, name, sections[{heading,body}]}], story: ONE rooted tree — a self-contained telling of the paper's experiments and results whose SPINE IS THE EXPLANATION, not the figure inventory. Node shape {id, name, narrative, ref: null|{kind:"concept", id}, figures: [{figure, note}], children[]}; root additionally carries tab + intro (intro format-validated). Nodes ref the paper's CONCEPTS (validated to exist; figure refs rejected); narratives may use [[wiki-links]]; the paper's figures attach to whichever node's claim they evidence (note >=40 chars ties figure to claim), every item attached exactly once. Validation: root id frozen as <pid>-experiments (deep-link anchor), tab required, narrative floors internal >=50 / leaf >=60 chars, node ids kebab-case, unique, and disjoint from the paper's paperStories node ids (both render as DOM ids on the same story page). Classification is item metadata only (marks which figure pages owe the visualization teaching, informs the story's shape) — it creates no sections. VALIDATION IS HARD for new papers: any paper not in merge.py's FIGURE_BACKFILL_PENDING set (the 6 pre-figure papers) must carry a complete figures entry — inventory, a page per item (name + sections, bodies >=100 chars), and the experiments story — or the whole apply is rejected. Figure pages render at site/figure/<pid>--<fid>.html; images ship to site/assets/figures/.

Merge commands: python tools/merge.py init|validate|concepts|themes|edges|superthemes|superedges|tissue-themes|stories|paper-stories|paper-overlay|walks|pages|intros|figures|figure-pages|figure-story [--aliases f]
Plus `apply <manifest.json>` (added stage 19): runs several subcommands as ONE transaction — one in-memory store, one validation, one atomic write. Required when adding a paper, because total-coverage validation (every concept themed, every theme in a supertheme + placed in every story, every edge in a connective theme, every paper in the overlay) makes cross-collection additions valid only together. `pages` entries may carry an optional "summary" to refresh a concept's one-liner.
