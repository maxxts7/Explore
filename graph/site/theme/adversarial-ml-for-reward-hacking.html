Borrowing adversarial ML to defend against reward hacking

If reward hacking is an agent finding the weak point in its own objective, the tools for finding weak points already existed elsewhere. This theme covers the defenses Concrete Problems (2016) imports wholesale from adversarial machine learning, treating a gameable reward signal as a close cousin of an image crafted to fool a classifier.

Starting from adversarial examples and the generative adversarial networks they draw on, the thread runs to counterexample resistance, which makes the transplant most explicit by hardening reward components with the same defenses built against adversarial inputs.

Several of the paper's proposed defenses against reward hacking are direct transplants from adversarial machine learning. Adversarial reward functions turn the reward signal itself into an active agent, modeled explicitly on generative adversarial networks, so the reward searches for scenarios the system rates highly but a human would rate poorly, rather than sitting still as a fixed target to be gamed. Adversarial blinding applies adversarial-training techniques to prevent an agent from gaining mutual information with parts of its environment it could otherwise exploit, such as how its reward is physically generated. Counterexample resistance goes furthest in making the borrowing explicit, proposing to harden learned reward components using the same adversarial-training and weight-uncertainty defenses developed against adversarial examples, inputs crafted to fool a classifier with imperceptible perturbations. Read as a set, these concepts make a specific claim: the reward-hacking problem is, in an important subset of cases, structurally the same problem as adversarial robustness, and the same toolkit applies to both.

Members — a guided walk

  1. Adversarial examples

    Adversarial examples, inputs often imperceptibly perturbed that cause a learned model to make confidently incorrect predictions, are the founding phenomenon this whole family of reward-hacking defenses borrows from. The claim uniting every concept in this walk is that reward hacking is, in an important subset of cases, structurally the same problem as adversarial robustness.

  2. Counterexample resistance

    Counterexample resistance is the most direct transplant: harden a learned reward component using the same adversarial-training and weight-uncertainty defenses developed against adversarial examples. The paper is explicit that this motivation only partially covers the remedy, since a reward component faces exploitation pressures beyond what image-classifier defenses were built for.

  3. Adversarial blinding

    Adversarial blinding also borrows the label "adversarial" and sits next to counterexample resistance in the paper's list of remedies, but it draws from a different corner of adversarial ML: rather than hardening a model against crafted inputs, it uses adversarial training to keep an agent from gaining mutual information with parts of its environment it could exploit, such as how its reward is physically generated.

  4. Generative adversarial networks (GANs)

    Generative adversarial networks supply the theme's other lineage: Goodfellow et al.'s generator-versus-discriminator framework, in which one network is trained explicitly to fool another, is the prior technique the next remedy is modeled on.

  5. Adversarial reward functions

    Adversarial reward functions turn that GAN shape into a reward-hacking defense, making the reward itself an active agent that searches for scenarios the system rates highly but a human would rate poorly, rather than a static target sitting still to be gamed. The GAN inspiration does not transfer perfectly, and the result is complementary to counterexample resistance, not a substitute for it: it attacks the outer loop of reward search where counterexample resistance hardens the reward model's inner representation.
